태스크 개요

1.1 AV-SELD 태스크

SELD(Sound Event Localization and Detection)는 FOA 음향을 기반으로 소리 이벤트의 종류, 시간, 방위각, 거리를 추정하는 문제다. AV-SELD(Audio-Visual SELD)는 여기에 영상을 추가 입력으로 사용하며, 검출한 소리가 화면 안(on-screen)에 있는지 밖(off-screen)에 있는지도 함께 판단한다.

1.2 챌린지 배경과 Moving-Camera

기존의 AV-SELD 태스크는 360도 전방위 음향과 비디오를 사용하여 소리 이벤트를 탐지하는 것을 목표로 했다. 하지만 DCASE 2025 Task 3에서는 360도 데이터가 아닌, 스테레오 음향과 제한된 시야각의 비디오를 이용한 AV-SELD 태스크를 다루었다.

그런데 DCASE 2025 Task 3의 결과에서는 음향에 영상을 추가해도 성능이 크게 오르지 않는 것으로 보고되었다. 학습 및 평가 데이터를 분석한 결과, 카메라가 클립 내내 고정되어 있어 소리의 발원지가 화면에 들어올 기회가 매우 적고, 영상 길이가 5초로 짧아 영상을 활용하기 어렵다고 판단했다.

실제로 DCASE 2025의 학습 및 평가 데이터에서 소리의 발원지가 화면 밖에 있는 비율은 약 75%에 달했다. 챌린지에 참여한 모델들이 소리의 발원지가 화면에 있는지 없는지를 맞추는 정확도도 70~80%대에 그쳐, 사실상 찍는 것과 비슷한 수준이었다.

우리는 데이터에서 영상을 활용할 수 있는 여건을 높이고 영상의 효과를 더 믿을 수 있게 평가하기 위해 Moving-Camera AV-SELD 챌린지를 기획했다. 같은 STARSS23 원본으로 두 가지를 바꾼 데이터셋을 구성한다.

  • 카메라 이동: 클립을 5초에서 20초로 늘리고, 그 동안 카메라가 좌우로 한 바퀴 돌고 위아래로도 기울어진다. 따라서 소리의 발원지가 화면에 들어올 기회가 많아진다.
  • 360도 방위각 추정: 기존 벤치마크는 앞, 뒤 방향 판단을 추정하지 않았다. 뒤쪽 부분의 방위각을 앞쪽으로 접어서 채점하므로 좌우 방향만 맞히는 형식이다. 이 챌린지는 학습, 검증, 테스트 데이터 모두 방위각 −180°~180°를 그대로 사용하여 비디오 정보를 이용한 앞 뒤 판단 성능을 평가한다.

영상을 잘 활용하는 모델이 점수에서 실제로 앞서는지를 평가한다.

상세 태스크 설명

2.1 입력 데이터

한 비디오 클립이 하나의 입력 단위이며, 예측도 클립마다 하나의 파일로 도출한다. 입력은 음향과 영상 데이터이며, 음향은 audio/{clip}.wav, 영상은 video/{clip}.mp4로 주어진다.

음향은 360도 방향의 정보를 담은 FOA 녹음을 스테레오로 변환한 것이다. 영상은 360도 영상에서 카메라가 바라보는 방향만 잘라낸 일반 시야각의 영상이다. 다만, 카메라 시점이 고정된 것이 아니라 카메라가 여러 방향으로 회전한다. 스테레오 음향은 좌우 방향은 비교적 잘 드러나지만 앞과 뒤를 구분하기 어렵다. 영상의 시야가 제한되어 있으므로 소리의 주인이 화면에 보이면 앞뒤를 구분하는 단서가 되지만, 화면 밖에서 나는 소리에 대해서는 영상에서 얻을 수 있는 정보가 없다. 반대로, 화면에 있는 소리라도 음향만으로는 앞뒤를 구분하기 어렵다. 즉, 영상과 음향을 모두 활용해야 방위각을 정확히 추정할 수 있다.

입력 데이터의 형식과 규약은 3절에서 자세히 설명한다.

2.2 출력 형식

출력은 비디오 클립의 매 프레임마다 발생하는 음향 이벤트에 대한 예측값이다. 각 프레임에서 활성 상태인 소리 이벤트의 클래스, 방위각, 거리, 그리고 화면 안에 있는지 여부(onscreen)를 추정한다. 한 프레임에서 여러 이벤트가 겹칠 수 있으며, 같은 클래스의 이벤트끼리 겹치는 경우도 있다.

2.3 정답 라벨 형식 (train, val)

labels/{clip}.csv는 헤더가 있는 csv이다. 아래는 형식을 보이기 위한 예시이다.

frame,class,source,azimuth,distance,onscreen
12,1,2,35,180,1
12,8,0,-120,250,0
13,1,2,34,181,1
열설명
frame0~199의 프레임 번호. 프레임 k의 기준 시각은 0.1k + 0.05초이다. 한 프레임에 여러 행이 있을 수 있고, 소리가 없는 프레임에는 행이 없다.
class클래스 번호 0~12 (3.3절).
source정답에서는 소리를 내는 사람의 번호이며 0은 사람이 아닌 소리이다. 예측에서는 임의의 정수를 쓸 수 있고 점수에 영향이 없다.
azimuth해당 프레임의 카메라 기준 방위각(도, 정수). 정면이 0이고 반시계 방향이 양수이며 범위는 −180~180이다.
distance소리까지의 거리(cm, 정수).
onscreen소리 방향이 카메라 시야 안이면 1, 밖이면 0.

2.4 제출 형식 (예측 csv)

test의 모든 클립에 대해 예측 csv를 하나씩 만든다. 파일 이름은 입력 클립과 같게 하고(test_00000.csv), 열 구성은 정답 라벨과 같다. 아래는 형식을 보이기 위한 예시이다. 

frame,class,source,azimuth,distance,onscreen
0,1,0,-60,150,0
0,8,1,100,300,0
1,1,0,-58,152,0
  • frame은 0~199이다. 이 범위를 벗어난 프레임은 채점에서 무시한다.
  • azimuth는 카메라 시점을 기준으로 한 방위각이다. (−180~180)
  • distance는 cm 단위의 정수를 권장한다.
  • onscreen은 0 또는 1이다.
  • source는 같은 프레임, 같은 클래스의 이벤트를 구분하는 번호로만 쓰인다. 같은 프레임과 클래스에서 최대 10개까지 인식한다.
  • 예측할 이벤트가 없는 프레임에는 행을 쓰지 않는다. csv가 없는 클립은 아무것도 예측하지 않은 것으로 채점한다.

데이터셋

3.1 원본 데이터 (STARSS23)

원본은 STARSS23이다. 핀란드 Tampere 대학교와 일본 Sony의 여러 방에서 사람들이 실제로 연기하며 촬영한 데이터로, FOA 형식의 음향과 360도 영상, 그리고 100 ms 단위로 달린 소리 이벤트 정답이 포함되어 있다. 이 챌린지는 개발용(dev) 데이터 중 음향, 영상, 정답이 모두 있는 녹음만 사용한다.

3.2 데이터 생성 방법

한 클립은 원본 비디오에서 20초(라벨 200프레임) 구간을 잘라 아래 순서로 만든다.

  1. 구간 선택. train은 영상 길이에 비례해 시작 위치를 무작위로 뽑으며, 같은 영상에서 구간이 겹칠 수 있다. val과 test는 녹음의 앞에서부터 겹치지 않게 모두 자른다. 정답이 거의 없는 구간과 16 bit 저장 시 클리핑이 생기는 구간은 제외했다.
  2. 카메라 궤적. 정답과 무관하게 시드만으로 정한다.
    • 좌우(yaw): ψ(t) = ψ0 + s·ω·t
      ψ0는 0~360° 균등 분포를 따르고, s는 회전 방향(±1), ω는 약 18°/s이며 U(0.9, 1.1)를 곱한다. 클립 하나에서 대략 한 바퀴를 돌도록 설계했다.
    • 위아래(pitch): φ(t) = −12.5° + 12.5°·sin(2πt/P + φ0)
      범위는 −25°~0°이고 주기 P는 10~20초에서 고른다.
  3. 음향 변환. FOA(W, Y, Z, X)를 카메라 방향 θ = −ψ(t)에 맞춰 샘플 단위로 스테레오로 변환한다. newY = sinθ·X + cosθ·Y, L = W + newY, R = W − newY.
  4. 영상 렌더링. 360도 영상에서 프레임마다 카메라 자세 (ψ, φ)에 해당하는 투시 영상을 직접 렌더링한다.
  5. 정답 변환. 원본의 세계 기준 방위각 az를 카메라 기준 방위각인 wrap(az − ψ)로 바꾼다.

모든 기준 시각은 라벨 프레임의 가운데이다. 프레임 k(0~199)는 클립 시작 후 0.1k + 0.05초이며, 영상 프레임, 카메라 자세, 음향 변환에 같은 시각을 사용한다.

3.7 유의 사항

  • meta 폴더. train과 val에만 있으며, 정답의 세계 기준 방위각과 고도(*_ext.csv), 프레임별 카메라 자세(*_traj.csv)가 들어 있다. 본 챌린지에서 다루지 않는 라벨이며, 참여자들 개개인의 모델 및 데이터 분석용으로 사용할 수 있다. 추론 입력으로 쓸 수 없다(5.2절).
  • 영상 코덱. mp4v는 일부 브라우저와 플레이어에서 재생되지 않을 수 있으니 주의한다. OpenCV와 ffmpeg로는 정상적으로 재생할 수 있다.

평가 지표

평가는 SELD의 표준 방식을 따르며, 모든 지표를 100 ms 프레임 단위로 세어 클래스별로 계산한 뒤 평균한다.

4.1 순위 기준 점수 (Fext)

순위는 위치까지 맞힌 검출 점수인 Fext로 정한다. 프레임과 클래스마다 예측과 정답을 방위각 차이를 기준으로 짝지은 뒤(헝가리안 매칭), 짝이 아래 조건을 모두 만족하면 TP로 센다.

  1. 클래스가 같다.
  2. 방위각 오차가 20° 이하이다. 오차는 360도 기준 원형 차이 |((a − b + 180) mod 360) − 180|로 계산한다.
  3. 상대 거리 오차 |dpred − dref| / dref가 1.0 이하이다.

짝은 지어졌지만 조건을 만족하지 못하면 FPspatial로 센다. 한 프레임에서 예측이 정답보다 많으면 초과분은 FP, 적으면 부족분은 FN이다. 클래스 c의 점수와 최종 점수는 다음과 같다. 

F_c = TP_c / ( TP_c + FP_spatial_c + 0.5 * (FP_c + FN_c) )
F   = 정답이 존재하는 클래스들의 F_c 평균

정답이 하나도 없는 클래스는 평균에서 제외한다. 채점 프레임 수는 항상 클립 길이(200)로 고정하므로, 마지막 소리 이후의 오검출이나 정답이 없는 클립에서의 오검출도 FP로 센다.

4.2 보조 지표

지표설명방향
FbasicFext와 같은 계산이되 정답과 예측의 방위각을 모두 앞쪽(−90°~90°)으로 접어서 비교한다. 즉, 앞뒤를 틀려도 감점되지 않는다. 기존 SELD 챌린지와의 호환을 위해 함께 보고한다.↑
DOAEext (°)클래스가 맞게 짝지어진 검출의 평균 방위각 오차.↓
RDE짝지어진 검출의 평균 상대 거리 오차(0.35는 35%).↓
OSA (%)On-screen accuracy. 짝지어진 검출 중 onscreen(화면에 표시된)을 맞힌 비율.↑

↑는 높을수록, ↓는 낮을수록 좋은 지표이다.

4.3 순위 산정 규칙

  • 순위는 Fext가 높은 순서로 정한다.
  • 모든 점수는 split 전체 클립을 한꺼번에 계산한 값이며, 클립별 점수의 평균이 아니다.

4.4 채점 코드 사용법

python score.py --pred {예측_csv_폴더} --ref val/labels --clip_len 200 \
                --modality audio_visual --out scores.json

출력은 ext(360도 기준)와 basic(앞 180도 기준) 두 방식에 대한 F, DOA 오차, 거리 오차, 상대 거리 오차, onscreen 정확도와 이 값들의 클래스별 결과이다. 이 페이지의 Fext, DOAEext, RDE, OSA는 json에서 각각 ext의 F, DOA_err, rel_dist_err, onscreen_acc에 해당한다. 코드는 score.py, metrics.py, seld_label_utils.py를 참조한다.
test 정답은 공개하지 않으므로 test 채점은 주최 측이 같은 코드로 수행한다.

챌린지 규칙

5.1 참가 방식

  • 개인 또는 팀으로 참가할 수 있다. 한 사람은 하나의 팀에만 속한다.
  • 제출물은 2.5절 형식의 submission.zip과 시스템 설명서이다. 시스템 설명서에는 모델 구조, 입력 특징, 학습 데이터, 외부 데이터와 사전학습 모델, 학습 방법, 파라미터 수 등의 정보를 기입한다.

5.2 데이터 사용 규정

  • 학습에는 이 챌린지가 제공하는 train과 val을 사용한다. 최종 모델을 만들 때 val을 학습에 합쳐도 되며, 이 경우 시스템 설명서에 명시한다.
  • test 입력은 추론에만 사용한다. test 입력으로 모델을 학습하거나 적응시키는 것(준지도 학습, 의사 라벨, 테스트 시 적응 포함)과 사람이 직접 라벨을 다는 것은 금지한다.
  • 하이퍼파라미터와 모델 선택은 val로 수행한다. test 결과를 보고 선택하는 것은 금지한다.
  • 카메라 자세 정보(meta/의 cam_yaw, cam_pitch, *_traj.csv)는 추론 입력으로 사용할 수 없다. 모델이 음향과 영상만으로 답하는 것이 이 챌린지의 전제이다. 학습 중 보조 목표로 사용하는 것은 허용하되 시스템 설명서에 명시한다.
  • 공개된 외부 데이터의 사용을 허용한다. 사용한 외부 데이터는 모두 시스템 설명서에 적는다.
  • 공개된 사전학습 가중치(예: ImageNet ResNet)의 사용을 허용한다. 이름과 출처를 시스템 설명서에 적는다.
  • 원본 STARSS23 개발 데이터를 직접 받아 이 챌린지와 같은 방식으로 다시 렌더링하여 추가 학습 데이터로 쓰는 것은 train에 속한 방의 녹음에 한해 허용한다. 생성 방법과 규모를 시스템 설명서에 적는다.
  • 데이터 증강은 자유롭게 사용할 수 있다. 다만 L/R 채널의 레벨이나 시간차를 바꾸는 변환은 방향 단서를 훼손하므로, 라벨을 함께 바꾸지 않는 한 사용하지 않는다.

5.3 공정성

  • test 정답을 알아내려는 모든 시도는 실격 사유이다. 여러 번 제출하여 점수 변화로 정답을 추정하는 것도 여기에 포함된다.
  • 규칙 위반이 확인되면 해당 제출을 리더보드에서 제외한다.

5.4 라이선스 및 인용

  • 데이터는 원본 STARSS23의 이용 조건을 따르며 연구와 챌린지 목적으로만 사용한다.
  • 이 챌린지의 결과를 발표할 때에는 STARSS23을 인용한다(7.6절).

베이스라인 모델

7.1 모델 구조

베이스라인은 DCASE 2025 Task 3의 공식 베이스라인(partha2409/DCASE2025_seld_baseline)을 이 챌린지의 데이터와 채점 방식에 맞게 수정한 것이다.

  • 음향 분기. 스테레오 로그멜 스펙트로그램을 CNN, 멀티헤드 셀프 어텐션, GRU에 통과시킨다.
  • 영상 분기. 프레임마다 ImageNet으로 사전학습된 ResNet-50 특징을 추출하고, 트랜스포머 디코더의 cross-attention으로 음향 특징과 융합한다.
  • 출력. 클래스당 3개의 트랙을 가지는 Multi-ACCDOA 표현에 거리와 onscreen 출력을 추가한 형식이다. 손실은 ADPIT를 사용한다.
  • 주요 수정. 360도 방위각(−180°~180°)을 다루도록 라벨 처리와 채점을 고쳤고, 영상이 이미 10 fps이므로 프레임 간격 계산도 고쳤다.

7.2 실험 설정 (프리셋)

프리셋모델영상 입력용도
B1음향만 사용없음영상 효과를 비교하기 위한 참고 모델

B3B2 + 시간 창 제한(±2프레임)실제 영상, 화면 전체영상을 더 활용하도록 개선한 모델

어떤 프리셋에서도 카메라 자세는 모델 입력으로 사용하지 않는다.

7.3 실행 방법

Colab 노트북(baseline/seld_challenge/colab_run.ipynb)의 설정 칸만 바꾸면서 위에서부터 실행하면 된다. 명령줄에서는 다음과 같이 실행한다.

cd baseline/seld_challenge
python run.py prepare  --dataset main20 --preset B2     # zip을 로컬에 풀기
python run.py features --dataset main20 --preset B2     # 음향, 영상 특징 추출 (캐시)
python run.py train    --dataset main20 --preset B2     # 학습 (매 에폭 val 채점, 최고 모델 저장)
python run.py eval     --dataset main20 --preset B2     # val 채점
python run.py predict  --dataset main20 --preset B2     # test 예측 csv와 제출 zip 생성
# 각 명령에 --set drive_root=결과_저장_폴더 --set seed=2 처럼 설정을 덮어쓸 수 있다.

기본 설정은 200 에폭, 학습률 0.001, 배치 64이며, 모델은 val의 Fext가 가장 높은 에폭으로 선택한다. 자세한 설정과 문제 해결 방법은 README_baseline.md에 있다.

7.4 베이스라인 분석 결과

  • 영상 자체의 효과는 거의 없다. test Fext에서 B2와 B2-0의 차이는 +0.2%p이고, 구간이 0을 크게 포함한다. B2가 음향만 쓰는 B1보다 3%p 정도 높은 것은 모델 구조가 커진 것으로 추정한다.
  • 영상은 다른 방식으로는 활용된다. 영상 모델은 앞뒤 혼동(DOAEext − DOAEbasic)이 약 11° 줄고 onscreen 정확도도 높다.
  • 영상 전처리의 시야 손실. 원래 전처리는 화면 가운데만 잘라 ResNet에 입력하므로 수평 시야 100° 중 약 60°만 사용한다. 화면 가장자리에서 나는 소리는 영상 모델이 보지 못하며, B3 설정이 이를 보완한다.
  • 시간 정보 부재. 원래 디코더에는 위치 인코딩과 시간 마스크가 없어서 음향 프레임이 영상의 모든 프레임을 동일하게 참조한다. 영상의 시간 위치는 모델이 데이터에서 스스로 알아내야 한다.
  • 과적합. 모든 모델이 심하게 과적합한다. 학습 손실은 계속 내려가지만 val 손실은 초반 에폭에서 최소가 된 뒤 다시 오른다.
